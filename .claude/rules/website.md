# Website Standards

`website/` is the TapTalk marketing site, a separate TanStack Start project. The "no web tech" rule in
`CLAUDE.md` applies to the app, not to this folder. Nothing in `website/` is imported by the app.

## Framework
- TanStack Start (React) on Vite, in prerender mode: every route is prerendered to static HTML
  (`prerender: { enabled: true, crawlLinks: true, autoSubfolderIndex: true }`). SSR stays one config flip
  away, never a rewrite.
- Hosted on Cloudflare Workers with Static Assets through `@cloudflare/vite-plugin` and `wrangler.jsonc`.
  Prerendered HTML is served as assets; the Worker only runs for paths that are not assets.
- When unsure about an API, read the docs before writing code, never guess from memory:
  https://tanstack.com/start/latest/docs/framework/react/overview (guides: `static-prerendering`,
  `spa-mode`, `hosting`, `seo`, `geo`, `css-styling`, `routing`) and
  https://developers.cloudflare.com/workers/static-assets/ plus
  https://developers.cloudflare.com/workers/wrangler/commands/.

## CLI first
- Scaffold only with `npx @tanstack/cli@latest create` and explicit flags. Never hand-assemble a project.
- Dependencies only through `pnpm add` / `pnpm add -D`. Never edit `pnpm-lock.yaml` by hand. Node 24, pnpm 10.
- Cloudflare only through the `wrangler` CLI (`wrangler deploy`, `wrangler types`, `wrangler dev`). No tokens
  in config, commands, or logs.
- Run scripts as `pnpm <script>` so the pinned local versions are used.

## TypeScript
- Strict everywhere: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`,
  `verbatimModuleSyntax`.
- No `any`, no `@ts-ignore` or `@ts-expect-error`, no non-null `!`, no casts to silence the compiler. Fix the type.
- `.ts` and `.tsx` only. Props are explicit `interface` or `type` declarations.
- `routeTree.gen.ts` is generated by the router plugin. Commit it (TanStack convention, so type-checking works
  without a build) and never edit it.

## Structure
- One component per file. Page sections live in `src/components/sections/`, shared primitives in
  `src/components/ui/`, interactive client-only pieces (the pill canvas, the flow diagram) in
  `src/components/interactive/`.
- Content is data, not JSX. Copy, comparison rows, FAQ, setup steps, and logos are typed objects in
  `src/content/`. Visible sections and JSON-LD render from the same objects so they never drift.
- Plain CSS: design tokens from the content guide as custom properties in `src/styles/`, one CSS Module per
  component. No Tailwind, no UI kit, no runtime CSS-in-JS.
- Static sections carry no client-side logic (no state, effects, or handlers). Interactive components
  are `lazy()`-loaded so the initial bundle stays minimal; the prerendered HTML paints before any JS runs.
- Files stay under ~200 lines. Split otherwise.

## Lint and format
- Biome only (`biome.json`). No ESLint, no Prettier. `pnpm biome check .` must pass clean before a commit.
  Recommended rules on, `noExplicitAny` is an error.
- `routeTree.gen.ts`, `dist/`, and `.wrangler/` are excluded from Biome.

## Comments
- `.claude/rules/comments.md` applies. Comment only a logical or trade-off decision, or a TanStack or
  Cloudflare behavior that is not obvious (head merge order, prerender filters, asset precedence). No prose,
  no banners, no restating the code.

## SEO, AEO, performance
- Every route declares `head()` with title, description, canonical, OpenGraph, Twitter, and JSON-LD via
  `scripts`. One `h1` per page, ordered `h2`/`h3`, real lists and tables.
- Ship `public/robots.txt` (allow GPTBot, PerplexityBot, ClaudeBot, Google-Extended), `public/llms.txt`, and
  the generated sitemap (`sitemap: { enabled: true, host }`).
- Rendered copy is ASCII only and follows `docs/plan/landing-content.md` section 1. No em or en dashes, smart
  quotes, ellipsis characters, or unicode symbols. Icons and logos are inline SVG.
- Budget: prerendered HTML, `server.build.inlineCss: true`, system font stack (no webfont requests), no
  third-party scripts, `prefers-reduced-motion` honored. Target Lighthouse 100 on every category. Measure
  before and after any change to the hero, pill, or diagram.

## Content source of truth
- `docs/plan/landing-content.md` defines structure, copy, comparison data, and the truth guardrails
  (section 24). Follow it. Never publish a claim it marks unverified.

## Commits and deploy
- `.claude/rules/commits.md` applies. Work on `feat/landing-page`. Never commit `node_modules/`, `dist/`,
  `.wrangler/`, or secrets.
- Deploy with `pnpm run deploy` (check, typecheck, build, then `wrangler deploy`). Never bare `pnpm deploy`,
  which is pnpm's own workspace command. Run `pnpm exec wrangler deploy --dry-run` first.
